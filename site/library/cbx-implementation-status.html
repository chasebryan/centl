Research library · Erdős–Straus · ES+

Implementation note

CBX is a separate X-ray and finite-cover research kernel: same mathematical finite cover, hidden-lane measurement, crash-preserving state, and a true inverse signed-box orientation.

Canonical source note in the repository

Status: active experimental research kernel implementation

Primary platform: Fedora-family GNU/Linux. Ubuntu is a secondary Linux portability check.

Production boundary: cbis.kernel 1.2.0 remains the production letter engine.

Claim boundary: this page records software and finite-search semantics. It does not establish an adaptive K law and does not prove Erdős–Straus.

Separate job, separate state

cbis.kernel asks whether the production cover disposes of a hard prime. cbx.kernel asks what every lane would have done independently, even when W already solved the target. The production order remains W → I → N → L; CBX X-rays underneath it without changing the verdict.

Finite grade

\Gamma=(F,K_I,E_N,A_L)

The default grade is (11,400,300,400). Named run grades are immutable. A different finite strength requires another run name.

Crash preservation

  • An entered target finishes all lane measurements before SIGINT/SIGTERM is honored.
  • Sweep resumes after the last fully processed integer; home resumes at the first unprocessed S.
  • A hard crash may replay an uncheckpointed batch, but it does not skip it.
  • A crash-truncated final JSON append is trimmed on restart; the analyzer also tolerates only that incomplete EOF case.
  • One writer owns a named run at a time. The POSIX lock is released automatically if the process dies.
  • Unique-letter counts are reconciled from durable per-run markers.

Exactness boundary

At the same finite grade CBX uses the same mathematical W/I/N/L predicates and ordering as cbis. CBX intentionally does not reproduce cbis’s eventual bounded-factorization failure mode: it uses deterministic 64-bit Miller–Rabin and Pollard-rho factorization. Its external-NR Jacobi path is unsigned-64-safe.

True inverse signed-box engine

CBX now implements the constructive Lane-I orientation named by the ES+ letter equation:

k \to C \to p=4C-k

For each admissible shift k and hard residue h mod 840, it enumerates only the six compatible classes

C \equiv (h+k)/4 \pmod{210}

and evaluates the vacancy condition on C before the generated p is consulted against the hard-prime map. That keeps the search genuinely C-first.

./centl es cbx inverse --hi 1000000 --i-max 400
./centl es cbx inverse --hi 100000 --i-max 80 --verify

The verification mode redundantly runs the p-first Lane-I recognizer over the same finite target universe and requires both cover membership and the minimal first k to match. The first CI equivalence check through 100,000 at K_I=80 passed with zero mismatches on GNU/Linux.

This does not yet establish that inversion is faster. The engine reports the number of C candidates, generated vacancy hits, covered hard primes and residual hard primes so the two orientations can be benchmarked honestly.

Adaptive-K research loop

The analyzer tracks the observed first-depth frontier and can directly falsify candidate rules such as K(p)=ceil(c log p) or K(p)=ceil(c (log p)^2).

It also computes the conservative finite calibration

c_{obs}=\max_{p\ observed} k_I^*(p)/B(p)

for all targets and separately inside R, together with the exact prime forcing each maximum. These are finite calibration statistics only.

First clean census

The deterministic default-grade census reached a sweep cursor of 234,540,000, recorded 401,752 Mordell-hard-prime X-rays and produced zero production letters. The finite observed Lane-I record was 107 at p=8,803,369; inside R the Lane-I p99 was 27.

The deliberately aggressive rule K(p)=ceil(2 log p) already fails 244 of 102,502 measured R targets in that corpus.

Regression gate

The dedicated GitHub Actions workflow uses Fedora-family GNU/Linux as the primary CBX baseline and Ubuntu as a secondary Linux check. It exercises the root launcher, the known 2521 X-ray, deterministic finite censuses, analyzer output, immutable-grade rejection, and inverse-vs-recognition equivalence.

macOS and Windows are not CBX support targets. Compatibility there may happen naturally through the surrounding codebase, but those systems do not drive this research kernel.

Next targets

  1. Accumulate deeper fixed-K corpora, especially inside R.
  2. Benchmark k → C → p inversion against p → k → C recognition as X and K grow.
  3. Archive publication-grade raw streams outside git with checksums.
  4. Correlate new first-depth records with factor structure, box size, spectrum, defects and López depth.
  5. Keep trying to break candidate K envelopes before attempting a theorem.
  6. Investigate whether W, N or L admit constructive inversions that reduce rather than increase total work.

Erdős–Straus remains open. CBX is an X-ray and finite-cover research instrument, not a proof engine.
