Research library · Erdős–Straus · ES+

Construction note

An exact finite implementation of the signed-box Lane-I cover in the constructive orientation k → C → p.

Canonical source note in the repository

Kernel: cbx.kernel 0.1.0

Primary platform: Fedora-family GNU/Linux.

Claim boundary: this is a finite cover construction and benchmarking instrument. It does not prove an adaptive K law, asymptotic superiority of inversion, or Erdős–Straus.

The orientation

The ordinary recognition path starts from a hard prime:

p \to k \to C=(p+k)/4 \to \delta_k(C).

CBX also implements the constructive orientation:

k \to C \to p=4C-k.

Only six C classes per shift

For a Mordell-hard target p ≡ h (mod 840), where

h\in\{1,121,169,289,361,529\},

and an admissible k ≡ 3 (mod 4), the generated C must satisfy

C\equiv(h+k)/4\pmod{210}.

Thus each shift needs only six compatible residue classes modulo 210 rather than all positive C.

Two C-major candidate modes

Strict C-first is retained as the pure constructive baseline. It factors and evaluates every hard-compatible C before consulting the finite target map.

Target-gated remains k-first and C-first in its outer traversal, but after generating p=4C-k it cheaply rejects a generated p when it is not a hard prime, when a smaller shift has already covered it, or when the coprimality condition fails. Only then does it factor C and evaluate the signed box. Since k is increasing, these gates cannot change cover membership or the minimal first shift.

Exact first depth

Shifts are visited in increasing order, so the first mark records

k_I^*(p)=\min\{k:\delta_k((p+k)/4)=0\}.

The engine can save p TAB k_I*(p) hit files and the Lane-I residual set separately.

Executable equivalence check

./centl es cbx inverse \
  --hi 100000 \
  --i-max 80 \
  --segment 25000 \
  --verify

--verify runs the p-first recognizer over the same finite hard-prime universe and requires both membership and minimal first-k agreement target-by-target. A single disagreement causes a nonzero exit.

The CI equivalence interval through 100,000 at K_I=80 passes with zero mismatches on Fedora and Ubuntu GNU/Linux.

What the benchmark found

Exact inversion does not imply faster inversion. The Fedora 44 three-repeat benchmark at X=100,000, K_I=80 found:

  • strict C-major factorization ratio: 20.198020×; wall ratio: 12.190308×;
  • target-gated C-major factorization ratio: 1.000000×; C-enumeration ratio: 20.198020×; wall ratio: 1.325060×;
  • shift-major factorization ratio: 1.000000×; active-visit ratio: 1.000000×; wall ratio: 0.992221×.

The shift-major timing is treated as practical parity within timing noise, not a speed theorem. See the full Lane-I orientation benchmark.

Commands

# Default target-gated C-major cover
./centl es cbx inverse --hi 1000000 --i-max 400

# Pure constructive baseline
./centl es cbx inverse --hi 1000000 --i-max 400 --strict-c-first

# Shift-major survivor frontier
./centl es cbx shift-i --hi 1000000 --i-max 400 --verify

# Three-way benchmark
python3 research/erdos-straus/cbx.kernel/bench_i.py \
  --hi 100000 --i-max 80 --repeat 3

Research frontier

The important next question is no longer whether inversion can be implemented. It can. The benchmark says the next target is the geometry of the work itself: profile yield and cost per shift, then decide whether each shift should be generated C-major, traversed shift-major, or left to recognition.

A hybrid is explicitly allowed. It remains an empirical engineering policy until separately proved.

Erdős–Straus remains open. Exact finite inversion is a computational instrument, not a proof.
