Mirror policy

FCF preservation is designed around a simple rule: a URL is not a backup. A resource is considered preserved only when FCF controls a copy of the bytes and records an immutable identity such as a full Git commit or SHA-256 digest.

Current public state: this HTTPS directory is live infrastructure for indexing FCF-hosted material. The complete CENTL dependency preservation set is being established separately and must pass its integrity/provenance checks before this page labels those artifacts as mirrored.

The exact backing store may move as FCF infrastructure grows. The site structure is intentionally independent of that storage decision so a future domain can preserve stable paths.

Integrity is not authentication

SHA-256 detects byte changes when the expected digest is already trusted. It does not, by itself, prove who published the expected digest. FCF should authenticate checksum manifests with an established signing system rather than inventing a new hash or signature scheme.

Canonical source

Until an item is explicitly marked mirrored here, use the CENTL repository and official releases as the distribution source.
