# CENTL v0.14.0 — Oasis

**Release codename:** Oasis
**Version:** 0.14.0
**Platform:** GNU/Linux
**Release posture:** consolidation, hardening, and stable-baseline release

> v0.13.0 was the Mirage. v0.14.0 is the Oasis.

CENTL v0.14.0 — Oasis is a deliberate consolidation release. The v0.13.0 development line reached a release-candidate state but was never formally published as a stable CENTL release. Rather than preserve that intermediate boundary as an artificial public release, Oasis incorporates the validated work from that line together with CARAVAN and MIRAGE, then establishes a new reviewed baseline.

Oasis is therefore broader than a normal feature increment. Its release gate includes repository reconciliation, removal of obsolete release automation, documentation cleanup, security remediation, supply-chain review, and full validation of the integrated GNU/Linux distribution.

## Included systems

### CENTL core

Oasis retains CENTL's exact-first numerical contract: exact input remains exact where the admitted mathematics permits, approximations carry explicit evidence, unsupported work remains visible, and machine-facing assurance classes cannot be promoted by untrusted semantic tooling.

### CENTL-SCi v0.0.2-Caramels

Caramels remains the current scientific interaction generation, including deterministic mathematics and physics interpretation, evidence-backed presentation, persistent user workspaces, and controlled BUILD/self-extension workflows.

### CENTL-MIRAGE

Oasis introduces the first stable local MIRAGE bootstrap: **Mathematical Introspective Recursive Autonomous Growth Engine**.

The Oasis boundary includes:

- bounded local design-document ingestion;
- SHA-256 source identity;
- provenance-preserving Specification IR;
- typed goal and capability graphs;
- deterministic hard-requirement conflict detection;
- capability-gap analysis and existing-capability reuse;
- machine-readable evidence obligations;
- non-mutating candidate transactions;
- explicit blocking of ambiguous, conflicting, or policy-prohibited requests;
- local `start`, `ingest`, `analyze`, and `status` workflows.

Oasis does **not** claim autonomous source mutation or autonomous promotion into verified core. Candidate transactions remain staged metadata and must cross the appropriate engineering and assurance gates before activation.

### CENTL CARAVAN Phase 1

Oasis includes the completed CARAVAN Phase 1 **local laboratory** for content-addressed, authenticated artifact preservation and availability.

The laboratory includes:

- immutable content-addressed storage with whole-file and deterministic chunk SHA-256 identities;
- Ed25519 pseudonymous carrier identity and proof of possession;
- signed policy-acceptance receipts;
- TUF-authenticated artifact catalog consumption;
- outbound-only laboratory carrier/coordinator transport;
- bounded transfer and polling behavior;
- verified multi-carrier retrieval with automatic bad-carrier quarantine/fallback;
- hostile-transfer handling for corruption, reordering, truncation, and appended data;
- local join/status/leave lifecycle;
- a reproducible one-command local laboratory.

CARAVAN's governing invariant remains:

> A carrier may provide bytes, but a carrier may never define which bytes are trusted.

Oasis does **not** enable arbitrary public volunteer enrollment. Production relay deployment, public enrollment, abuse operations, final telemetry/privacy policy, and other public-network rollout gates remain later work.

## Consolidation and repository hygiene

The Oasis preparation process treats repository state as part of release quality. Obsolete v0.13.0 one-shot tag/gate-observer automation is removed, stale release references are reconciled, repository structure is documented, active pull-request state is reduced to intentional work, and historical branches are classified before any destructive cleanup.

Historical branches may remain temporarily as preservation refs when the available tooling cannot prove that deleting them would preserve unique work. A branch name is not part of the supported Oasis runtime surface.

## Security posture

Oasis is gated on source remediation rather than alert suppression. Security work includes:

- immutable GitHub Action pins with accurate version annotations;
- least-privilege workflow permissions;
- dependency review;
- GitHub Actions security analysis;
- release and installer supply-chain boundaries;
- filesystem, path, symlink, and atomic-write boundaries;
- native/process/protocol resource limits;
- CARAVAN trust, identity, metadata, transfer, and quarantine boundaries;
- MIRAGE provenance, workspace, and candidate-authority boundaries.

Security review establishes evidence for the release boundary; it is not a claim that any nontrivial software is free of all possible vulnerabilities.

## Version history note

`0.13.0` remains visible in development history and documentation where historically useful, but it is not presented as a formally published stable release. Oasis is the public stable successor to v0.12.0.
